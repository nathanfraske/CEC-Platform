# Bounded terminal-landing cohorts

`cec_terminal_landing_schedule.py` rederives eligible targets from the actual
saved Source before grouping them into finite cohorts. A cohort has at most
four distinct keepers; the same keeper can be handled again in a later cohort
for another actual terminal, with new exact-Source evidence. Board names,
reference numbers and fixed coordinates do not choose the geometry.

This avoids spending the work budget on inactive via faces or replaying a
landing already improved in a preceding cohort. Discovery records are not
authority: Source hashes, runtime/dependency identities, actual native keeper
identity and the entire construction rule are checked again. Malformed,
duplicated, stale or unowned target data never supplies geometry permission.

`build/root_run_bounded_terminal_cohorts_20261020.py` runs at most four native-
screened cohorts and stops on no accepted change. Intermediate intake is bound
to a complete actual native report and is explicitly not a whole-board grade.
No current budget, route width, drill, component placement, factory constraint
or release gate changes. Full parent current, partition, Kelvin, reference,
ground-return, native DRC and final grading must pass across the entire chain.

The bounded search is not proof that every visible contour is clean. Legacy
keeper contours can survive a later centerline miter and leave a tab even when
the retained tracks and new barrel landing are correct. Such a stale contour
needs a separately received conductor/contact-preserving keeper rebuild;
running unchanged waves or weakening a Source/contact gate does not fix it.
