## Tooling bug found + fixed during promotion (not a part issue): the FIRST
## promotion attempt failed `kicad-cli sym/fp upgrade` with an opaque
## "Unable to load library" on AOD4184A specifically. Root-caused by
## isolating single symbols and diffing a kicad-cli-upgraded copy against a
## raw extraction: (1) a `descr`/`ki_description` string containing a
## LITERAL embedded newline (a multi-line datasheet-link blurb easyeda2kicad
## emitted for this part) breaks kicad-cli's loader for the older/compact
## easyeda2kicad symbol format, even though the parens balance and a real
## from-scratch parser (cec_sym_audit.py) reads it fine -- fixed by
## flattening any multi-line string literal to one line before upgrading
## (cosmetic-only field); (2) re-labeling an un-upgraded symbol body under a
## modern `(version 20251024)` header (this agent's own first-draft
## approach) makes kicad-cli parse it via the strict modern path, which the
## older compact body does not satisfy (missing the per-symbol
## `(embedded_fonts no)` child real KiCad-10 output always carries) -- fixed
## by running `kicad-cli sym upgrade` on each SOURCE file individually
## BEFORE extracting/concatenating, so every carved block is already fully
## modern and self-contained. Both fixes are generic (in the promotion
## script, not part-specific); every part in this library was re-verified to
## load cleanly via `kicad-cli sym/fp upgrade --force` after the fix.

## Real-part / BOM correction found (annotated, not silent):
- **HoRX-50W-xxR (C2923747 family) is NOT a small radial-lead THT resistor.**
  Its DigiKey mechanical listing (live-checked 2026-07-16,
  digikey.com/en/products/detail/shenzhen-milliohm-electronic-co-ltd/
  HoRX-50W-30R-5/27557628) gives: package/case "Axial, Box"; CHASSIS MOUNT
  with flanges + SOLDER LUGS; body 50.00 x 29.00 x 15.49mm (aluminum housed
  wirewound). This matches DESIGN-SHEET.md's own doctrine (Sec B floorplan
  zones name "alu-shell resistors on two facing plates"; Sec G "R-plate lug
  fields: M4 lug pads, wire gauge table per bank current") -- the resistor
  is genuinely OFF-BOARD, chassis-plate-mounted; only its wire leads land on
  the PCB. Drew `HoRX_50W_WireLug_2Pin.kicad_mod` as a 2-PAD WIRE-TO-BOARD
  LANDING pattern (generic THT pads sized for 16-18AWG lead wire), NOT a
  resistor-body silhouette -- the correct representation for a chassis-
  mounted part. Symbol: reuses the platform's own `cec-vendor:R_Small` (the
  same 2-pin resistor glyph already reused across every physical size class
  platform-wide, e.g. the module shunts) with this footprint override, Value
  = the leg's resistance. This is a documentation/footprint correction, not
  a BOM MPN change -- the BOM doc's own text (Sec 1 "R-banks" row) never
  claimed "radial THT" itself; that framing was this task's OWN Phase-A
  brief, corrected here per CLAUDE.md's "annotate, never silently" rule.

## Design decision: Littelfuse 0287 ATOF fuse "footprint" (fp to mate the
## 3557-10 holder): rather than drawing a SEPARATE 2-pin generic Fuse symbol
## and solving a pin-to-multi-pad footprint mapping puzzle, the promoted
## Keystone 3557-10 HOLDER symbol (4 real pins, matching its 4 real pads
## 1:1 -- pins 1+2 bridge one side/net, 3+4 the other, per the holder's own
## pad coordinates) is reused DIRECTLY as each fuse POSITION in the
## generator: ref class "F" (fuse), Value = the actual Littelfuse 0287xxx
## current rating per instance, footprint = the holder land (what actually
## solders to the board -- the fuse element itself plugs in, it has no
## board footprint of its own). This is simpler and more electrically
## honest than inventing a 2-pin symbol mapped onto a 4-pad land. A future
## BOM-precision pass could split this into two BOM lines (holder + the
## specific replaceable fuse P/N) if that level of purchasing detail is
## wanted -- flagged in FOLLOWUPS.md, not implemented here.

## Design decision: OPA2277UA-2K5 channel usage (the "engine limit" flag in
## this task's brief). Verified: the vendored symbol IS multi-unit
## (OPA2277UA_1_1 = channel A: OUTA/1, INA-/2, INA+/3, V-/4, V+/8;
## OPA2277UA_2_1 = channel B: OUTB/7, INB+/5, INB-/6) and cec_sch.py's
## generation engine always emits `(unit 1)` on a placed instance -- so a
## SECOND unit of the SAME instantiated symbol cannot be wired. RESOLUTION:
## every CC-loop leaf populates ONE OPA2277UA-2K5 package using ONLY channel
## A (pins 1/2/3/4/8); channel B (pins 5/6/7) is intentionally left
## no-connect/spare. This sidesteps the engine limit entirely (channel B is
## never wired, so the unit-1-only restriction never bites) and matches the
## Tester Pro BOM's own per-loop quantity convention (Sec 1 "CC loop amps"
## row: qty 8 for Pro's 8 loops, i.e. one package per loop, not one package
## per TWO loops). A future cost-down pass COULD pair 2 loops per package
## (drawing a flattened single-unit dual-section local symbol to route
## around the engine limit) -- flagged as a documented BOM-optimization
## option in FOLLOWUPS.md, not implemented here to preserve per-loop
## isolation and match the Pro-tier precedent.
