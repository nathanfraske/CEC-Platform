### Sequencing note

Derived directly from Microchip's *PolarFire SoC FPGA Board Design Guidelines* (DS60001681H), §1.1 and §1.13 — **primary source, read directly, not summarized secondhand**:

1. **Hard rule (POR circuitry, no tolerance):** VDD, VDD18, and VDD25 must each ramp *monotonically* from 0V to their minimum operating voltage — "any deviation... will compromise device functionality." This is a soft-start-quality requirement on each converter individually, not a relative-order requirement between them — satisfied by using standard COT/CCM bucks with clean soft-start (MPM3833C qualifies).
2. **VDDI3 (JTAG bank)** must be powered *before or at the same time as* VDD/VDD18/VDD25.
3. **VDDI5 (SGMII bank + MSS dedicated clocks)** must be powered *before or along with* VDD, and must reach its datasheet minimum *before* VDD reaches functional level *and* before MSS executes its first instruction (T_CPU). **This is why VDDI5 is populated on every SKU, not just NET** — it gates basic MSS boot, independent of whether the SGMII transceiver itself is used.
4. Since VDDI3 and VDDI5 are both folded into U6 (shared 3.3V domain per the datasheet's own VDDI/VDDAUX same-regulator rule), a *single* supervisor on U6's output (U9, TPS3839K33) satisfies both (2) and (3) simultaneously by gating EN on U3/U4/U5/U7/U8 — this is a PG-daisy-chain built from small supervisor ICs, not a dedicated multi-channel sequencer.
5. **Chosen approach: PG-daisy-chain via cascaded TPS3839-family supervisors, not a dedicated sequencer IC** (e.g. UCD90xxx-class). Justification: the datasheet's actual requirement is "before or at the same time" plus per-rail monotonicity — a loose ordering constraint, not a tight ms-level skew spec. A big multi-channel sequencer would be real overkill for a 2-tier gate; TPS3839 is already a sourced platform part (hub-standard, C96333) and does triple duty here: sequencing gate (U9), §1.13-mandated external brownout detection on VDD/VDD18/VDD25 (U9/U10/U11/U12 — §1.13: "for brownout detection on any PolarFire supply (including VDD, VDD18, and VDD25), use external brownout detection circuits"), and DEVRST_N drive (U9's RESET output, satisfying the datasheet's "drive DEVRST_N with a POR chip" option — chosen over the passive "1kΩ-to-VDDI3" alternative because it's an active, real POR rather than a static pull-up).
6. XCVR_VREF is not required (differential 125MHz refclk chosen) and I/O calibration gating on VDDA+XCVR_VREF is therefore moot on this design.

### Open items

1. **SoC and DDR pricing are RFQ-only** — MPFS095TS-1FCVG484I and the LPDDR4 candidate both returned "request a quote" behavior at every distributor reachable from this environment (Mouser/DigiKey/Octopart blocked scripted price-break reads; microchipdirect/microchipusa confirm quote-gating + an 18-week SoC lead time). Get real RFQs before D-ENT-3 lock.
2. **VDD core headroom** — a single MPM3833C (3A) is sized to the low end of the estimated core-current range with no Power Estimator run to confirm. If the real TSN-switch/data-plane fabric utilization pushes core current past ~2.5A, parallel a 2nd MPM3833C (MPS supports current-sharing) or step up to a higher-current sibling.
3. **Two TPS7A20-family decivolt SKUs (1.0V, 2.5V) and two TPS3839 threshold codes (~1.8V, ~2.5V) are named by extrapolating a confirmed-real naming convention** (verified via the 1.8V and 5.0V TPS7A20 siblings, and the 3.3V/0.9V TPS3839 siblings, both live on LCSC) but their own exact LCSC stock/price was not independently pulled this pass — confirm at BOM finalization. If unavailable, both families offer adjustable variants as a fallback.
4. **125MHz differential oscillator (Y2) is flagged out of stock at its LCSC listing** — a real DigiKey-orderable alternate (Abracon AK3AAIGDDF1-125.0000T, ClearClock family) is named; re-verify stock/price before layout.
5. **SPI-master boot-mode strap polarity (SPI_EN/IO_CFG_INTF, R-SPI)** — I provisioned the real resistor footprints/values Microchip's Fig 1-7 reference design shows, but did not independently re-derive which pull direction selects "master mode, QSPI quad enabled" vs the figure's own default network. Confirm against DS60001681H Fig 1-7 + the *PolarFire Family Programming User Guide* at schematic capture — getting this backward affects whether the board boots.
6. **WP#/HOLD# on U2 (QSPI flash) are mode-dependent**: in true quad-SPI boot (this design's intent) they're driven as IO2/IO3 by the SoC's QSPI controller, not pulled up as static WP/HOLD — no pull-up resistors provisioned here for that reason; flag if firmware ends up using single/dual SPI instead of quad.
7. **Scope boundary, explicitly excluded from this BOM**: (a) AC-coupling caps on the SGMII differential pair itself (between U1 and the GbE PHY) — this sits at the SoC/PHY interconnect and more naturally belongs to subsystem B (PHY rails) or a connector-adjacent pass; flag for cross-subsystem reconciliation. (b) DETECT external ADC / rail-sense dividers — explicitly assigned to subsystem C per `hub-ent-variants-plan.md` §3 ("PolarFire has no native ADC... added to BOM-C open items"), not duplicated here.
8. **DDR fitted-vs-LIM-only is still an open firmware-team question** (`hub-ent-spec-sheet.md` open row #2) — this BOM keeps the DDR block cleanly separable (one buck, one chip, one resistor, four caps) so either answer is a population change, not a redesign.
9. Two research sub-agents dispatched for cross-verification did not return usable results in time (one hit an internal 32MB response-size limit re-fetching the same guide I read directly; one got stuck mid-fan-out) — not a blocker, since the primary-source PDF read plus direct LCSC/DigiKey verification covered the same ground with higher confidence than a secondhand summary would have.
