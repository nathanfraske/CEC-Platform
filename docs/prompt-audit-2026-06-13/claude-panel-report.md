# Prompt Audit — Claude Panel Report (2026-06-13)

## Summary

This audit examines the prompt construction across every seat of the CEC full-stack closed-loop pipeline (T1 intent_manager, T4 worker_panel, T5 auditor, T6 vision narrate, T7 corpus_fit_review, T8 V4 batch audit, and the CL24 adversarial verifier charters). The dominant failure class is **grounding-by-omission**: seats are repeatedly instructed to reason about board geometry — footprint refs, the shunt/Kelvin corridor, the actuator fence, the ratified corpus — using prompts that never interpolate the very facts the deterministic layer already computes in-container. The single most actionable cluster is the **T1 intent_manager prompt**, which supplies a ref-based waypoint vocabulary but zero ref inventory, zero coordinates, no enum/existence validation, and no actuator fence; the confirmed `U5` hallucination is one symptom and several findings collapse into one fix (inject a placed-footprint + net manifest into the prompt and validate against it). A second cluster is **prompt-vs-reality contracts**: the CL24 spec-conformance charter is labeled "ratified corpus" but fed the run's ephemeral scratchpad; the T5 auditor is imperatively told to fill a field the same prompt declares inert; the cloud auditor path is ungrammared where the deepseek path is grammar-bound. A third cluster is **A/B-baseline contamination**: the control lane's intent carry-forward is not lane-gated, so augmented-learned waypoints leak into the signed-only baseline and bias the measured lift. Thirty findings were confirmed against source (several re-graded for downstream deterministic containment); three were rejected as factually wrong about the actuation paths. Findings below are grouped so that one fix retiring several is called out explicitly, ordered most-actionable-first within each severity band.

## High severity

### H1. T1 intent_manager has no board ref/net inventory, no enum, no validation — the U5 hallucination class (grounding + schema)

**Tier:** T1 — intent_manager (`cec_fullstack.py:691-721`, `INTENTS_SCHEMA:156`)

**Failure.** The waypoint vocabulary the schema demands is ref-based (`{ref, offset_mm}` / `{between:[refA,refB]}`), but the prompt supplies **zero board refs and zero coordinates**. The only refs anywhere in the prompt are the two literal example tokens `U2`/`U1` inside the example sentence (`cec_fullstack.py:706`). The injected GR-01 grid carries only net-name lists (`contested`/`order`) and grid-cell indices `(i,j,ratio)` for hotspots (`cec_router.py:1259-1268`) — no footprint refs, no mm. `INTENTS_SCHEMA` leaves `net`/`ref`/`between` as free strings with no enum and no existence check (`cec_fullstack.py:163,169,172`), and the only post-filter checks key presence: `ok = [i for i in intents if i.get('net') and i.get('waypoints')]` (`cec_fullstack.py:716`). So a schema-valid output can name a footprint or net that does not exist, and that is exactly the observed `U5`/`U4`/`U6`/`U7` hallucination (run logs `docs/fullstack-run-2026-06-13/intents/round-005..033.json`; auditor flags it in `round-008/009/016/021-sonnet.json`). The eps-8pin board has `U1,U2,U3,U10,U11,U20,U21,U30,U31,RS1,RS2,J1,J5,D1,D2` — `U4/U5/U6/U7` do not exist.

**Code evidence.** Prompt builder `cec_fullstack.py:698-709`; schema free-strings `:163,169,172`; presence-only filter `:716`; grid is net-keyed/cell-indexed `cec_router.py:1259-1268`; `cec_fr02._fp_center` raises `KeyError('intent ref ... not on board')` (`cec_fr02.py:59-64`) and `compile_intents` catches it, appends to `failures`, and `continue`s — a **silent drop**, no signal back to the seat (`cec_fr02.py:191-193`).

**Containment (why it degrades rather than crashes).** The deterministic `compile_intents` guard means a hallucinated ref is *dropped*, not misrouted — so the harm is **degraded steering**: the seat repeatedly burns its 4-waypoint budget on a non-existent anchor and the intended corridor-avoidance never materializes for that net, with a fail-safe to `prev_intents` on total failure. This is why the route never crashes but the round is wasted.

**Fix (one fix, retires H1 + several mediums).** Build a compact board manifest once in-container from `board.GetFootprints()` (the same pcbnew access `pour_facts`/`congestion_grid` already use): the placed-ref list with `(ref, value/role, x_mm, y_mm)` for routing-relevant parts (connectors, ESP, CAN xcvr, shunts, sense ICs) plus the net→endpoint-ref map for the contested nets, and the board-outline bbox. Inject it into the T1 prompt body. Then **make `net`/`ref`/`between` enums populated from that manifest** (or validate at `intent_manager()` return and drop/re-prompt with a logged reason), so a hallucinated ref is caught at emit instead of silently swallowed downstream. Drop or replace the bare `U2`/`U1` examples with refs drawn from the real inventory. `cec_fr02._fp_center` already exists; a sibling that dumps all refs+centers feeds this directly.

> **This manifest also resolves M1 (corridor geometry) and M2 (hotspot cell→ref mapping)** — see those entries. Inject the manifest once and three grounding findings close.

### H2. T1 is never told the actuator fence — it can lock force-protected stubs onto Kelvin/sense nets and pinned shunt/INA refs with no downstream guard (constraint)

**Tier:** T1 — intent_manager (`cec_fullstack.py:691-721`)

**Failure.** A per-run fence exists and is enforced **everywhere except the T1 generation path**. `_resolve_board_fence(board)` builds `fence['nets']` (every Kelvin-pair net) + `fence['refs'] = BOARD_PINNED_REFS['eps-8pin'] = ('RS1','RS2','U20','U21','U2')` (the shunts + INA sense ICs + CAN xcvr), and `cec_fs_actuator.is_fenced()` refuses any auditor/V4 delta that targets them (`cec_fs_actuator.py:102,165`). But `intent_manager`'s prompt (`cec_fullstack.py:698-709`) contains none of this — and actively *invites* steering the sense regions ("route contested/failing nets AROUND the sense regions (shunt Kelvin windows)") without ever naming which nets are the locked Kelvin nets or that `RS1/RS2/U20/U21` may never be anchors. Critically, `compile_intents` (`cec_fr02.py:161-225`) applies **no fence check**: a waypoint whose ref/net merely exists is compiled into a real `SetLocked(True)` stub and then upgraded to `(type protect)` by `force_protect_in_dsn` (`cec_fr02.py:228`, applied at `cec_overnight_directed.py:197`). The `is_sense_net` regex backstop in `cec_fs_actuator.py:63` lives only in the finding→delta translator and is never reached on the model-driven path.

**Code evidence.** Fence resolved `cec_fullstack.py:1077-1090`, enforced only in `finding_to_delta` (`cec_fs_actuator.py:102-104`) and `v4_structural_escape` (`:165`); T1 prompt has no fence (`cec_fullstack.py:698-709`); intents flow `ipath -> _exec_route_one -> route_one_worker -> route_directed -> cec_fr02.compile_intents` (`cec_overnight_directed.py:186`) with `allow_at_mm=True`, and `compile_intents` checks only net-existence (`cec_fr02.py:175`) and clear-spot (`:196`) before locking (`:211`). The "belt-and-suspenders … a finding can never steer a locked Kelvin template" comment (`cec_fullstack.py:1084-1085`) describes the **actuator path only**.

**Why high.** A T1 intent on `/SENSEC2_HI` anchored to `RS2` compiles into a locked, force-protected stub that **reshapes the very §6.8 owner-ratified Kelvin window the prompt told the seat to keep clear**, with no downstream guard — the exact class the auditor-side fence exists to refuse.

**Fix.** Prompt + code, because a free-string ref field cannot self-police. (a) Add a verbatim fence line to the T1 prompt: `FENCED — never target these nets or anchor to these refs: nets=[…kelvin/sense…], refs=[RS1,RS2,U20,U21,U2].` (b) Defensively filter in `intent_manager()` before returning — drop any intent whose net `is_fenced()` and any waypoint whose `ref` is in `fence['refs']`, logging the drop — **or** pass the fence into `compile_intents` so it rejects fenced targets the same way `finding_to_delta` does.

### H3. CL24 spec-conformance charter is labeled "ratified corpus" but fed the run's ephemeral manager_rules (empty on control rounds) (grounding + constraint)

**Tier:** CL24 — spec-conformance charter (`cec_verifier.py:104-110`; ctx at `cec_fullstack.py:1336`)

**Failure.** `_slice_spec` labels its input "RATIFIED RULES / LOCKED DECISIONS (the governing corpus extract)" (`cec_verifier.py:80-82`) and the charter system prompt asks the seat to refute findings that "contradict a ratified rule/locked decision (cite which)" (`:106-109`). But the caller populates `ctx['rules_excerpt'] = json.dumps(lr_view['manager_rules'])` (`cec_fullstack.py:1336`) — the loop's auto-generated, RULE_CAP-capped, novelty-deduped standing rules, **not** the ratified corpus and **not** the CLAUDE.md/spec locked decisions (RJ-45-not-Mini-Fit, the pin-allocation table, the Kelvin fence, the §6.4 shunt values). On a control round `lr_view['manager_rules']` is `[]` (`cec_fullstack.py:1184`), so the charter receives `'[]'` as its entire corpus; the verifier code itself tags the result `empty_corpus` (`cec_verifier.py:318`). A charter named for locked-decision conformance, never shown the spec or the locked decisions, cannot refute a finding that proposes violating one — it can only abstain or rubber-stamp. Refute calls feed the precision/calibration latch (`cec_verifier.py:158-191`), so mis-grounded refutes corrupt charter calibration too.

**Code evidence.** Slice label `cec_verifier.py:80-82`; charter question `:106-109`; ctx build `cec_fullstack.py:1336`; control-round blanking `:1184`; `empty_corpus` self-tag `cec_verifier.py:318`. `CORPUS_BRIEF` (the real promoted corpus, `cec_fullstack.py:405`) is built once per run and prepended to T1/T4/T5 (`:712/742/884`) but is **not** wired into `rules_excerpt`, and the verifier seat (`cec_verifier.py:247`) never receives it.

**Fix (trivial — the corpus is already loaded).** Build `rules_excerpt` from real ratified knowledge: `CORPUS_BRIEF` + a compact locked-decisions/fence summary (pin allocation, RJ-45 lock, Kelvin fence nets+refs, §6.4 shunts) + the manager_rules. If `manager_rules` must remain, relabel them in the slice as "in-run standing rules (unratified)" so the seat does not treat them as ratified ground truth.

### H4. EI-02 control lane is contaminated — augmented-learned waypoint intents leak into CONTROL rounds via a single carry-forward variable (contamination)

**Tier:** EI-02 control lane / T1 intent_manager

**Failure.** The control lane is the signed-only baseline whose purpose is to measure the augmented lane against a run with **no** run-learned steering. The code carefully strips `manager_rules`/`scorer_penalties`/`refuted_metrics` into `lr_view` for control rounds (`cec_fullstack.py:1184`) and suppresses the deterministic corridor-avoid additions (`:1198-1205`). **But `intents` is a single variable** initialized once (`:1163` `records, intents, rnd = [], ovd.INTENTS[board], 0`), reassigned every round unconditionally by `intents, why, src = intent_manager(...)` (`:1193`), and passed straight back as `prev_intents` next round, injected verbatim into the T1 prompt as `LAST ROUND intents: %s` (`intent_manager` `:705/709`, `json.dumps(prev_intents)[:1500]`) **regardless of lane**. With `CONTROL_EVERY=4` (`:231`), a control round (e.g. round 8) is preceded by an augmented round (round 7), so the augmented lane's learned waypoint plan flows into the control round's T1 prompt. The A/B aggregate (`:1601`) is therefore biased: the "signed-only" control board is partly routed with augmented-learned corridor-avoidance, under-reporting the augmented lane's true lift.

**Code evidence.** `cec_fullstack.py:1163` (single `intents` var), `:1193` (unconditional reassign + next-round `prev_intents`), `intent_manager` `:705/709` (verbatim inject), lane suppression `:1198-1205` (handles only `pending_corridor_avoid`, not the model's own carried intents), `lr_view` blanking `:1184` (no equivalent reset for `intents`).

**Fix.** Maintain two carry-forward slots (`intents_aug`, `intents_ctrl`) so the lanes never cross-feed, or on a control round pass `prev_intents=ovd.INTENTS[board]` (the signed seed) and do not let a control round's resulting intents overwrite the augmented carry-forward — mirroring how `lr_view` zeroes the other run-learned steer.

## Medium severity

### M1. T1 "route AROUND the sense regions / mid-board shunt corridor" names a region the prompt never locates (grounding)

**Tier:** T1 — intent_manager. **Re-graded high→medium** (the corridor instruction is a soft "Prefer", and `pour_integrity_ok` is a blocking gate that cannot ship a clipped board — `cec_fullstack.py:1260-1264`; the item4 corridor-avoid lever fires deterministically from `pour_clipped_nets` at `:1167/1198` regardless of the T1 guess). The prompt instructs routing "AROUND the sense regions (shunt Kelvin windows)" and "keep I2C/CAN OUT of the mid-board shunt corridor" (`cec_fullstack.py:701-708`), but the corridor is never given as coordinates or a bbox. The deterministic side already computes it — `pour_facts` derives each `SENSEC*_HI/_LO` zone bbox (`cec_fullstack.py:507-509`) — but none is interpolated into T1. **Fix:** inject the `SENSEC*_HI/_LO` pour bboxes and/or shunt/INA refs+positions as the labeled keep-out. **Resolved by the H1 board manifest.**

### M2. T1 GR-01 hotspots are raw grid-cell `(i,j)` indices with no net/ref mapping (grounding)

**Tier:** T1 — intent_manager. The grid carries `cell_mm` (so a cell *is* convertible to mm, `i*cell_mm`), but there is **no cell→net or cell→ref mapping**, and the usable signal (the `contested`/`order` net-name list) is already separately provided — so the raw `(i,j,ratio)` hotspot list (`cec_router.py:1259-1267`) is effectively noise the model may anchor decisions to (`cec_fullstack.py:703` frames it as actionable). **Fix:** resolve hotspots to mm centroids and attach the dominant overlapping nets/refs before serializing, **or** drop the raw index list and pass only the net-keyed list. **Resolved by the H1 board manifest.**

### M3. T5 auditor `proposed_lever`: imperatively told to "name THAT lever" yet the same prompt says it has "NO direct effector" (ambiguity)

**Tier:** T5 in-loop auditor. **Re-graded high→medium** (`root_cause` is banked regardless and `failure_class` still actuates GR-02, so a discarded `proposed_lever` degrades efficiency, not safety). Within one prompt the seat is told "name THAT lever in `proposed_lever`" (`cec_fullstack.py:795-797`) and then told `proposed_lever` "is VERIFIER-CONTEXT-ONLY today … it has NO direct effector — the corridor-avoidance lever fires DETERMINISTICALLY from `pour_clipped_nets`, not from this field" (`:824-828`). Confirmed: `inject()` never reads `proposed_lever` (`:950-1002`), the only T5-driven effector is `failure_class=='placement' -> GR-02` (`:1371-1380`), and `proposed_lever` is passed solely as verifier ctx (`:1347`). Catalog line 126: "every auditor proposed_lever became actuator noop/refused." The seat burns reasoning authoring a precise, discarded plan while under-investing in the `failure_class` call that actually steers. **Fix:** lead with what actuates — "Your `failure_class` drives the loop: placement→GR-02; scoring→may price a metric (only if a gate-passing candidate exists); routing→records the diagnosis. `proposed_lever` is ADVISORY CONTEXT ONLY — fill it briefly, do not over-invest." Stop using the imperative "name THAT lever" for an inert field.

### M4. T5 cloud auditor path is ungrammared/unvalidated while the deepseek path is grammar-bound — same role, two reliability classes (schema)

**Tier:** T5 — sonnet/opus cloud path (`cec_fullstack.py:847`) vs deepseek (`:884`). **Re-graded high→medium** (latent in the run; the verdict does **not** drive escalation — it is only logged at `:1361/1367` and used as an anchor-presence check at `:284` — loop escalation is driven by the T4 panel at `:1224-1231`). The deepseek path binds `AUDIT_SCHEMA` as `json_schema` strict and hard-guards `if 'verdict' not in out: return {'verdict':'repair',...}` (`:884-890`); the cloud path instead `json.load(open(out_path))` (`:864`) with no schema, no enum check, no required-key check, fed only `_AUDIT_JSON_TEMPLATE` prose (`:847`). The **load-bearing** consumer is `failure_class`: `:1371` `placement_attr = (sj.get('failure_class')=='placement')` drives the T0 placement actuator (`:1374`) — a non-enum cloud value silently disables T0. **Fix:** after loading the cloud file, validate against `AUDIT_SCHEMA` and coerce missing/invalid `verdict` to `'repair'` exactly like the deepseek guard; reject/normalize out-of-enum `failure_class`; show the literal enum sets inline in the cloud prompt.

### M5. T5 auditor `verdict` enum duplicates the T4 panel's `action` with no auditor-specific definition and no effector (ambiguity)

**Tier:** T5 in-loop auditor (schema). **Re-graded medium→low in the verifier pass**, recorded here for completeness. `AUDIT_SCHEMA` requires `verdict ∈ {accept,repair,escalate}` (`cec_fullstack.py:142,151`) — the same enum as `PANEL_SCHEMA.action` (`:186`) — but the auditor is a diagnostician whose verdict is consumed only as an anchor-presence flag (`:284`) and a log line (`:1361/1367`); no effector branches on it, and `_audit_prompt` (`:790-828`) never defines what "accept" means *for the auditor* as distinct from the panel. Role bleed: two seats sharing one action vocabulary applied to two jobs. **Fix:** drop `verdict` from `AUDIT_SCHEMA`, or role-define it ("your read of whether this round's board is acceptable AS DIAGNOSED, independent of the panel; it does not drive routing").

### M6. T5 "Penalisable keys" advertises metrics the scorer cannot apply and includes gate metrics the same prompt forbids pricing (schema)

**Tier:** T5 auditor (`cec_fullstack.py:823` vs `PENALISABLE:78` / `_PENALTY_METRIC:349`). **Re-graded high→medium** (latent — all 21 observed auditor findings had `scorer_penalty=null`; the seeded penalties at `:1129` are all in `_PENALTY_METRIC`). The auditor is shown `Penalisable keys: {list(PENALISABLE)}` = `(drc, unconnected, length, vias, plane_signal_mm, gate_fail, kelvin_unrouted, diffpair_unrouted, max_T)` (`:78-79,823`), but `_PENALTY_METRIC` only knows `{drc, unconnected, plane_signal_mm, length, vias, max_T}` (`:349`). `inject()` admits any `metric in PENALISABLE` and logs it `accepted:raised` (`:962,987-989`), yet `_penalty_weighted_base` silently drops any metric not in `_PENALTY_METRIC` (`rk is None -> continue`, `:360-362`) — so a penalty on `gate_fail`/`kelvin_unrouted`/`diffpair_unrouted` is **recorded-accepted but never reweights ranking** (a phantom lever). Separately, `diffpair_unrouted` is advertised but never produced in `cec_fullstack` (only in the separate `cec_inloop_audit.py:73`). Pricing gate metrics also contradicts the same prompt's "price only when a gate-passing candidate already exists" rule (`:796-798`). **Fix:** derive the advertised list from `_PENALTY_METRIC`, not `PENALISABLE`; either remove the gate-derived metrics from `PENALISABLE` or wire them into `_PENALTY_METRIC`; drop `diffpair_unrouted` until produced; make `inject()` reject metrics absent from `_PENALTY_METRIC` rather than logging them accepted.

### M7. T7 corpus_fit_review prompt instructs `coverage_note`, but the schema lacks the field and sets `additionalProperties:false` (schema)

**Tier:** T7 corpus_fit_review (`cec_judge_local.py:961` vs `CORPUS_FIT_SCHEMA:889`). The system prose says "The coverage_note says what evidence was elided — if precedent is thin, lower confidence rather than bluffing" (`:961`), but `CORPUS_FIT_SCHEMA` has no `coverage_note` property and `additionalProperties:false`; under the strict `json_schema` grammar (`_chat_json:259`) the model cannot emit it — the instruction is dead, and a model that follows the prose toward an illegal shape is steered into the overrun/empty-content path that triggers the scribe fallback. **Fix:** delete the `coverage_note` sentence and fold the "lower confidence on thin precedent" guidance into the existing `confidence`/`insufficient_precedent` fields, or add `coverage_note` (string, not required) to the schema.

### M8/M9. T4 worker_panel safety lens is told to judge "plane integrity" with only `plane_signal_mm`, the diffpair/kelvin lens judges a finished boolean, and the schema field `action` is never named in prose (grounding + ambiguity)

**Tier:** T4 worker_panel (safety lens). *Four overlapping confirmed findings collapse into one fix.* **Re-graded** (the most severe variant high→medium/low) because the deterministic `pour_integrity_ok` gate forces `gates_pass=False` on a clipped pour **before** the panel finalizes, the panel cannot accept a gate-fail (`cec_fullstack.py:757-758`), and the panel runs (`:1224`) *before* `vision_pour_check` computes the facts (`:1237`) — so a confabulated "plane fine" verdict cannot ship a broken board.

The cluster:
- **Plane integrity has no backing data.** `_LENSES[0] = 'safety (hard gates: kelvin, diffpair, plane integrity)'` (`:725`), but the payload `m` is the 8-key scalar dict `{gates_pass, kelvin_ok, diffpair_ok, drc, unconnected, plane_signal_mm, max_T, objective}` (`:732-733`). `plane_signal_mm` is a single board-wide scalar = sum of signal-copper-on-plane mm (`cec_score.py:277`), a different quantity from pour fragmentation. The integrity facts (per-net island counts, `foreign_cross`, `components`) live in `pour_facts` (`:488-518`) and are never passed to T4, and that role was explicitly moved to determinism (`vision_pour_check` docstring `:536-541`: "emits a FLAG, never a verdict").
- **diffpair/kelvin are pre-computed booleans the seat cannot evaluate or override** (`m` carries only `diffpair_ok`/`kelvin_ok`), so the seat can only restate or confabulate a rationale at temp 0.0 — structurally redundant with the deterministic gate.
- **The schema field `action` is never named in prose** (`:738-741` says only "accept/repair/escalate"; `PANEL_SCHEMA` requires `action` at `:188`); only the strict grammar saves it. The catalog records the safety seat debating `decision` vs `action` — a small-model load symptom that re-exposes if any path weakens the grammar.

**Fix (one reframe).** Reframe the safety lens to its real job: "the hard gates `kelvin_ok`/`diffpair_ok`/plane integrity are ALREADY computed deterministically. Do NOT re-judge them. Given the gate state, decide repair vs escalate (router-fixable vs structural)." Drop "plane integrity" from the label (determinism owns it), or feed the lens `det_clipped_nets` + per-net island counts from `pour_facts` framed as facts-to-confirm (mirroring the T6 facts-alongside protocol). Name the schema field explicitly in the prompt ('reply with field "action": one of accept|repair|escalate').

### M10. T4 three lenses share one accept/repair/escalate rule keyed to "hard gates pass AND your lens" — collapsing the decorrelated panel toward one gate-driven vote (ambiguity)

**Tier:** T4 worker_panel (progress + finishing lenses). The per-lens system prompt is identical except the `{lens}` token: "accept only if hard gates pass AND your lens is satisfied; repair if more router effort could fix it; escalate if stuck/structural" (`cec_fullstack.py:738-741`). For the **progress** lens ("is effort spend still buying improvement?", `:727`) this is self-contradictory — a converged-but-failing board should escalate, not keep repairing — and the lens is given a single round's metrics (`:732-733`) with **no cross-round delta**, so it cannot judge improvement. The **finishing** lens (cosmetic vs structural DRC) is told to gate accept on hard-gate pass, conflating orthogonal axes. The majority tally (`:753-756`) then reflects redundancy, not independent perspectives — exactly the local-minimum thrash the auditor prompt was added to fight, emitted by the lens whose job was to call diminishing returns. **Fix:** give each lens its own rule. Safety: accept iff gates pass. Finishing: accept iff residual DRC is cosmetic-class, "gate state is the safety lens's job, not yours." Progress: keyed to the objective/metric trajectory across rounds (give it the prior 1-2 rounds' objective/drc/effort), NOT to hard-gate pass.

### M11. T4 structurally over-escalates — every lens told "escalate if stuck/structural" but only safety has structure data, and there is no escalate→repair clamp (calibration)

**Tier:** T4 worker_panel. All three lenses get the identical "escalate if stuck/structural" instruction (`:738-741`), but the finishing and progress lenses see only single-round scalars with no geometry/trajectory. The only post-rule is the accept→repair clamp (`:757-758`); there is **no symmetric escalate→repair downgrade**, and escalate bumps router effort hardest (`passes+14/opt+20`, `:1228-1229` vs repair's `+8/+12`). Two ill-equipped lenses agreeing on a speculative "escalate" burns budget on a re-plan the metrics did not justify. **Fix:** give the progress lens the cross-round delta it is asked to judge, and either restrict "escalate if structural" to the safety lens or require escalate to be the majority before bumping to the escalate tier (an escalate→repair downgrade when only one lens escalates). *(Note: with 3 voters, escalate winning already requires 2 votes — a majority, not a plurality; the cost is wasted budget, not a safety regression.)*

### M12. CORPUS_BRIEF is ~83% off-family noise for a routing task, the largest block every seat reads first (contamination)

**Tier:** T1/T4/T5/T8 (all CORPUS_BRIEF consumers). `promoted_corpus_brief` keeps every promoted/general entry up to 13000 chars, only `[scope:]`-tagging off-family entries rather than dropping them (`cec_fullstack.py:405-451`). Measured on eps-8pin: 35 entries, only 6 in-scope; the remaining 29 (~7000 of 8183 body chars) are 12VHPWR connector pin-ratings, REF3030 drift, shunt load-life, measurement/calibration policy, judge-authority rules — none bearing on FR-02 waypoint placement. It is prepended **first** (`:712,742,884`), framed "treat as authoritative, do not contradict or re-derive" (`:449`), ahead of a few hundred bytes of actual round data, on small thinking workers (`cec-worker-vision`, temp 0.2/0.3, 1500-token panel ceiling). On T4 the brief is ~40x the judgment payload; the catalog's observed safety-seat schema near-slip corroborates the load. **Fix:** drop off-family entries by default for the generation/routing seats (T1/T4) — pass only the `n_in` subset already computed — or, if platform-wide knowledge is wanted, keep only entries with empty `scope.families` AND a routing-relevant `kind` (layout/plane/keepout/thermal), excluding measurement/judge/conn-rating families. Place the round-specific task ahead of the brief.

### M13. CORPUS_BRIEF truncation at `max_chars=13000` is latent-silent and cuts by FILE SORT ORDER, not relevance (contamination)
