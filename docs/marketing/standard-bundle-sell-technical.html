What each board in the bundle brings

Modules are tier-agnostic and degrade gracefully — any module works in any Hub.

24-PIN ATX

motherboard main power

4× INA238 — full V·I·P on all four system rails (12 / 5 / 3.3 / 5VSB), Kelvin-sensed.

EPS 8-PIN

CPU power

INA238 per cable (×2) + §6.13 transient front-end — 12 V current + spike flag.

PCIe 8-PIN

GPU power (legacy)

INA238 per cable (up to ×3) + §6.13 front-end — per-cable current + transients.

12VHPWR

GPU power (600 W)

6× INA240 per pin + rail V (REF3030) + 2× NTC — sees the imbalance that melts.

HUB

aggregate & host link

CAN → USB, 16 MB persist flash, 3-source power, board-temp NTC.

04

How it reaches the user — no app to build

modules→ CAN → Hub→ USB (CDC + HID sensors) → OS sensor API→ AllMyStuff

The bundle presents itself as a standard composite USB device: a CDC stream for the raw/verbose path and a HID sensor interface (voltage / current / power / temperature usages) that Windows and Linux read natively, driverless. Stable identity is a real VID/PID plus the factory-MAC serial. No first-party dashboard is required — the data lands in the OS and any consolidator picks it up.

Alpha — validated

Every Standard board exists as a working prototype. The sensing architecture above is proven, not aspirational.

Beta — refining

Owner-approved refinements in flight: FTP jacks, INA238 supply reversion, the connector-daughterboard output, thermal-verified copper.

Firmware — the remaining work

The right column is specified down to the §-reference and the ALERT nets are wired at the parts. It is coding against a fixed contract, not open design.

Honest framing: EPS/PCIe §6.13 front-ends are on the schematics with routing pending; the 24-pin/EPS/PCIe carry the S3-MINI-1 today (spec targets the C6). Nothing above claims a firmware feature as shipping. Sources: Ground-Truth Spec v1.5.0 §§2.3, 6.1, 6.10, 6.13, 6.14; standard-tier review.
