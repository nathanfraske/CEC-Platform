comparing the two connector revisions' local minima._ Dashboard: http://localhost:8095 (run-dir `build/24pin-rev2-shrink`).

**The 90° (rev2) board is 21% smaller (6576 vs 8342 mm²)** and routes clean. The owner's hypothesis — rotating the
output connector lets the board pack tighter — is **confirmed at baseline**. (The L tucks the two 62.6 mm-long
24-pin headers into perpendicular edges instead of side-by-side, freeing the middle for the logic.)

## Both boards are at their rigid-shrink floor (0%)

The shrink-sweep (rigid narrow + smart re-pack of foreign parts, connectors/shunts fixed, route+score each step,
keep the smallest still-valid: kelvin held / unconn ≤ start / drc+clips within tol) found **0% on both**:
- **straight-through**: every step hits ONE unresolvable courtyard overlap — it is **connector-perimeter-bound**
  (the two 24-pin headers + RJ-45 + USB-C tile the edges; board is 86%+ footprint-filled). Floor = the current size.
- **90° (rev2)**: every step hits 16–20 overlaps — **densely part-packed**. The 3 big parts (ESP U1 45.5×39, J3,
  J4) are **75% of the 6576 mm²**, so there is almost no placement slack left to rigidly compress.

clip-tol was set generous (120) and repack=smart (try hardest) per the owner's "everything possible to save space"
— still 0% rigid. The size is **part-courtyard-bound**, which also means **pour-width reduction does NOT shrink the
outline** (parts collide before the pours do); the pour/thermal lever is orthogonal to size here.

## The real remaining lever — ~1270 mm² of dead space in U1's stale keepout (≈19%)

rev2's ESP **U1 carries a STALE embedded courtyard of 45.5 × 35.3 mm**, but the library footprint
(`cec-RF_Module:ESP32-S2-MINI-1_NoAntKeepout`) is already trimmed to **16 × 21.2 mm** (the 24-pin is wired-only —
no antenna keepout needed). So the board currently RESERVES ~**1270 mm²** of empty space around U1 (baseline
drc=0 → nothing sits in it). "Update U1 from Library" reclaims it; a **from-scratch re-placement that packs the
logic into that freed zone** could reach ~5300 mm² — **another ~17–19% on top of the 21%** (total ~36% vs straight).

The rigid shrink-sweep CANNOT capture this (it translates the far half rigidly; it does not re-place into U1's
freed pocket — and its overlap model already used the trimmed 16×21, so it sees no wall there). Capturing it needs
a **from-scratch re-place with the connectors pinned at the L positions** — delicate, because a blind re-place
strands the 4 rail shunts off the J3→J4 path and breaks kelvin (verified: 3 blind attempts on the straight board
all broke kelvin / left 9–17 nets unrouted). So this is best done **with render review**, not a blind overnight
auto-run.

## UPDATE — header-overhang lever lands 32% (owner hint, 2026-06-24)
Owner: "allow the 24-pin headers to overhang the edges so their board-mount through-hole stabilizers don't
mount on either." This was the unlock. The board outline was tight to the pads (margins L 3.3 / T 3.7 / R 1.5 /
B 1.9 mm) but those L/T margins were set by J3/J4's **NPTH stabilizer holes** (J3 at x=98.3, J4 at y=65.6 — the
leftmost/topmost features). Letting the headers overhang so the stabilizers fall in the off-board region lets the
outline pull in to the electrical pins + 0.7 mm.

- **Method (no re-place, no re-route — routing stays valid):** kept the committed rev2 routing intact, moved the
  Edge.Cuts in to (electrical-pad extent + 0.7 mm), re-poured GND. Scored the EXISTING routing (not a fresh route).
- **RESULT: 77.3 × 73.0 = 5647 mm² — kelvin ✓ / diffpair ✓ / unconnected 0 (preserved).** = **32% smaller than
  straight-through** (8342), 14% smaller than rev2-90deg (6576). Board: `build/24pin-rev2-tight/rev2-overhang-routed.kicad_pcb`;
  render `build/24pin-renders/rev2-overhang.png`; on the dashboard (:8095, run-dir build/24pin-compare).
- **Why this worked where re-place failed:** nothing moves, so the rails + kelvin + ESP routing all stay connected.
  A fresh re-route in the tight outline broke kelvin (the FR edge-keepout squeezes the connector escapes); keeping
  the routing avoids that entirely.
- **Remaining (finishing): DRC = 47 = 33 copper-edge-clearance (copper near the new tight edge — the known FR edge
  artifact, excluded from drc_placement) + 13 clearance + 1 courtyard.** Clean it with a re-pour at a proper edge
  inset + back the edge off ~0.3 mm (→ ~30% clean), or re-route with `CEC_NO_EDGE_KEEPOUT=1`. The stabilizer NPTH
  holes now sit off-board (the intended overhang) — drop them from the footprints on the next pass.

## UPDATE 2 — directed worker pipeline launched + 5VSB-safe overhang (2026-06-24)
- **5VSB input-side fix:** the aggressive (0.7mm-all-around) overhang clipped the 5VSB trace on the INPUT (J3)
  side, where the 24-pin input pins must fan in. Fixed with an ASYMMETRIC overhang — input(left)+2.5mm,
  output(top)/right+0.7mm, bottom+0.9mm. **79.1 × 73.2 = 5794 mm², kelvin/diffpair/unconn 0 PRESERVED (5VSB
  intact) = 30.5% smaller than straight.** DRC 31 (17 edge-clearance + 13 clearance + 1 courtyard; finishing
  re-pour). Board: build/24pin-rev2-tight/rev2-overhang-asym.kicad_pcb.
- **From-scratch rev3 (automated re-place): does NOT improve — breaks kelvin/routing (5 attempts).** A game plan
  (keep the 90° L + the proven rail core; fill the upper-right void; asymmetric overhang) was built + run through
  the stack; the legalize-based re-place strands the rails (unconn 7-17, kelvin False) every time. The rail core +
  kelvin need HAND placement; blind automation can't.
- **DIRECTED WORKER PIPELINE launched (owner's call) — the GATED alternative.** `cec_place_planner --run` on the
  24-pin (seed=rev2, cec-worker seat, --max-grows 0, CEC_NO_EDGE_KEEPOUT=1, 8h/200 rounds, out build/24pin-rev3-directed).
  It routes+scores every candidate and keeps ONLY valid (kelvin/unconn) improvements, so it can't ship a broken
  board. r1 the LLM worker correctly diagnosed the 208 clips (foreign ESP/CAN nets crossing the rail pours) and
  proposed an 11-ref region partition. NOTE: run() optimizes CLIPS (placement quality), not board SIZE directly —
  the path to a smaller board is: directed loop finds a tighter/cleaner VALID placement -> then overhang it.
  Dashboard :8095 (run-dir build/24pin-rev3-directed) for morning review.
